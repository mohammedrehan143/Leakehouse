## 2. Source Column Definitions

| Column Name | Source Type | Description | Lakehouse Target |
| :--- | :--- | :--- | :--- |
| `InvoiceNo` | Nominal / String | 6-digit integer uniquely assigned to each transaction. If the code starts with letter 'c', it indicates a cancellation. | `VARCHAR(20)` |
| `StockCode` | Nominal / String | 5-digit integer or alphanumeric code uniquely assigned to each distinct product. | `VARCHAR(50)` |
| `Description` | Nominal / Text | Product (item) name. May contain whitespace or missing entries. | `TEXT` |
| `Quantity` | Numeric / Integer | The quantities of each product per transaction line. May be negative for cancellations or adjustments. | `INTEGER` |
| `InvoiceDate` | Timestamp | Transaction date and time generated by the POS/checkout system. | `TIMESTAMP` |
| `UnitPrice` | Numeric / Float | Unit price in Sterling (£) per unit item. | `NUMERIC(12, 4)` |
| `CustomerID` | Nominal / Float | 5-digit customer identifier. Missing for anonymous/guest checkouts. | `VARCHAR(20)` (nullable) |
| `Country` | Nominal / String | Country where customer resides. | `VARCHAR(100)` |

## 3. Critical Analytical & Semantic Limitations

1. **Grain of Data**:
   - `InvoiceNo` does NOT identify a unique row. A single invoice contains multiple products (`StockCode`).
   - The true natural composite key is `(InvoiceNo, StockCode, InvoiceDate, Quantity, UnitPrice)`.
2. **Missing Customer IDs**:
   - Approximately 25% of records have `CustomerID = NaN` representing guest transactions. These must not be deleted blindly in the lakehouse; they must be preserved in Silver and flagged as `guest_checkout`.
3. **Cancellations & Negative Quantities**:
   - Invoices beginning with `C` or `c` indicate cancellations.
   - Negative quantities may also indicate stock adjustments, damages, or discounts.
   - They must be segregated into a documented returns/cancellations model rather than simply treated as customer returns.
4. **Zero or Negative Unit Prices**:
   - Some operational rows show `UnitPrice = 0.0` (manual corrections, gifts, system tests) or negative adjustments.
   - These must be quarantined or flagged with explicit anomaly tags.
5. **No Product Cost Data**:
   - The source dataset includes `UnitPrice` (selling price) but **NO product acquisition cost**.
   - Therefore, **gross revenue** can be calculated, but **profit and profit margins cannot be calculated** without a separately sourced cost table. Calculating profit without cost data is prohibited.
